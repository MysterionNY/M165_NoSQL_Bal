## Phase 1: Setup & Embedding-Wunder

### Erklärung: Was passiert im Hintergrund?

Wenn ChromaDB die Lebenslauf-Texte speichert, werden die Texte nicht nur als normaler Text abgelegt. Chroma verwendet eine **Embedding-Funktion**, um jeden Text in einen Zahlenvektor umzuwandeln, der die Bedeutung des Textes mathematisch beschreibt. Laut ChromaDB werden Dokumente beim Hinzufügen automatisch mit der Embedding-Funktion der Collection eingebettet; bei einer späteren `query()`-Abfrage wird auch die Suchanfrage eingebettet und per Vektorähnlichkeit verglichen. ([Manage Collections][1])

## Phase 2: Fehlerhafte KI-Abfrage

### Warum liefert `get(where=...)` keine passenden Resultate?

Die ursprüngliche Abfrage verwendet:

```python
collection.get(
    where={"text": suchanfrage}
)
```

Das Problem ist: `where` sucht in ChromaDB nach **Metadaten**, nicht nach semantischer Bedeutung im Dokumenttext. ChromaDB beschreibt `where` als Filter für Metadatenfelder, zum Beispiel `{"page": 10}`. ([Metadata Filtering][2]) In unserem Code wurden aber gar keine Metadaten mit dem Feld `text` gespeichert. Ausserdem wäre selbst ein Textvergleich nur exakt und würde nicht verstehen, dass „Frontend-Entwickler fürs Webdesign“ inhaltlich zu „responsive Benutzeroberflächen mit React und CSS“ passt. Aus diesem Grund müsste weiterhin nach Metadaten in dem Kontext gefiltert werden, da die Inhaltliche Filterung gar nicht erst vorhanden ist.

## Phase 3: Architektur-Reflexion

### Warum findet eine Vektordatenbank „Hund“ und „Welpe“, SQL aber nicht?

Eine SQL-Abfrage wie:

```sql
WHERE text LIKE '%Hund%'
```

sucht nur nach dem exakten Wort „Hund“. Wenn im Text nur „Welpe“ steht, gibt es keinen Treffer, obwohl die Bedeutung sehr ähnlich ist. Eine Vektordatenbank speichert Wörter oder Texte dagegen als Punkte in einem mehrdimensionalen Vektorraum. Begriffe mit ähnlicher Bedeutung liegen dort nahe beieinander. Deshalb kann eine semantische Suche erkennen, dass „Hund“, „Welpe“, „Haustier“ oder „junger Hund“ inhaltlich zusammengehören.

### Metadaten vs. Vektoren: Warum kombiniert man beides?

In der Praxis reicht semantische Suche allein oft nicht aus, weil man zusätzlich harte Filter braucht. Die Vektorsuche findet ähnliche Inhalte, aber Metadaten grenzen die Suche fachlich ein. ChromaDB unterstützt genau diese Kombination: `query()` kann semantisch suchen und gleichzeitig mit `where` nach Metadaten filtern. ([Metdata Filtering][2])

Beispiel aus HR & Recruiting:

Ein Manager sucht:

```text
Frontend-Entwickler fürs Webdesign
```

Semantisch könnten passende Personen mit React, CSS und Benutzeroberflächen gefunden werden. Zusätzlich möchte die Firma aber vielleicht nur Kandidaten aus Zürich oder nur Bewerber mit Senior-Level sehen. Dann könnte man Dokumente mit Metadaten speichern, zum Beispiel:

```python
metadatas = [
    {"bereich": "frontend", "level": "senior", "standort": "zuerich"},
    {"bereich": "devops", "level": "mid", "standort": "bern"},
    {"bereich": "data", "level": "junior", "standort": "zuerich"},
    {"bereich": "management", "level": "senior", "standort": "basel"}
]
```

Dann könnte man semantisch suchen, aber nur innerhalb eines bestimmten Bereichs:

```python
resultate = collection.query(
    query_texts=["Frontend-Entwickler fürs Webdesign"],
    n_results=2,
    where={"bereich": "frontend"}
)
```

Dadurch kombiniert man beides: Die Vektorsuche versteht die Bedeutung der Anfrage, während der Metadatenfilter harte Bedingungen wie Bereich, Standort, Jahr, Kategorie oder Senioritätslevel sicher einhält.
